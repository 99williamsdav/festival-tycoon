## Acceptance checks

1. Same benchmark configuration produces consistent authoritative output; timings may vary.
2. Wide passage improves controlled flow over narrow passage without changing demand/stock.
3. Full scenario completes with reconciled sales and released reservations; throughput is not inflated by despawning blocked guests.
4. Report measured 1x/4x behaviour and compare with technical targets, distinguishing headless throughput from rendered FPS.
5. Windows export launches with benchmark mode; previous functional and save/replay checks remain passing.
6. Mark every M0 gate Pass/Fail/Unverified with evidence. Unknown hardware/visual results are not passes.

These are required outcomes, not a prescribed test implementation. Add meaningful automated checks where feasible and report manual observations honestly.
