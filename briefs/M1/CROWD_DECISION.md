# Proposed M1 crowd-scope exception

Status: **Approved — 22 September 2026.** This bounded exception was explicitly approved for M1.00. It exists because `IMPLEMENTATION_PLAN.md` §3 says core foundation failures should be fixed before feature work, while the accepted M0.10 report records the promised 1,200 full-fidelity gate as Failed and representative rendered targets as partly Unverified.

## Proposed decision

Permit a bounded M1 progression scope of 20–50 full-fidelity people only if M1.00 first demonstrates **50 people in one shared `GameSession`/occupancy world with multiple destinations**. M0.10's eight isolated sessions are not that proof. Any unmet M1.00 feasibility target returns a measured decision/options package and halts dependent M1 briefs.

## Non-negotiable existing architecture

- One simulated person remains one ticket and one wallet; no invisible paying population.
- Off-camera people execute identical authoritative logic. `TECHNICAL_SPEC.md` §6 permits mesh/animation LOD only.
- Simulation/population aggregation or simulation LOD is **not approved**. It is a future alternative requiring explicit written user approval under `TECHNICAL_SPEC.md` §15.
- The clock remains four ticks/festival-second and 20 festival-seconds/real-second: 80 authoritative ticks/real-second at 1×. No tick-rate reduction to pass.
- M0's original 1,200 failure and later 800/1,200 ambitions remain visible and unchanged. Passing 50 is not universal capacity.

## Early gate and stop rule

On declared hardware, M1.00 must measure the existing `TECHNICAL_SPEC.md` §13 targets and operational evidence: representative stable 60 FPS at 1×; actual attained 1× and reported 4×; save under two seconds/load under five seconds; input stalls during save/reports; peak memory; tick/frame percentiles; path searches/cache hits, blocked-route age, agent/queue/job counts, draw calls and allocation rate where available. Unmeasured is Unverified, not Pass.

If any feasibility target is missed, stop before M1.01. Profile first and return bounded options. Shared route caching or staggered request budgets may be proposed only when profiling supports them and must retain determinism, save equivalence, collision/separation and exact swept navigation. No structural rewrite is the default.

## Recorded decision

Proceed with M1.00 under the hard-stop terms above. This approval applies only to the bounded 20–50 scope and early shared-world feasibility gate; it does not approve M1.10's later settlement-insufficiency choice or any dependent M1 implementation before M1.00 is accepted.
