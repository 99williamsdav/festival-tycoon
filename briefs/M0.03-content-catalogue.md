Status at authoring: Not started. Milestone: M0 foundation.

## Assignment

A tiny authored scenario loads from versioned data and malformed input fails before a session starts.

Dependencies: M0.02 accepted.

Read [shared execution rules](README.md#shared-execution-rules), then these targeted sections of the repository-root documents: TECHNICAL_SPEC.md §§5, 12; CONTENT_AND_BALANCE.md §§1, 4. Read additional sections only when needed to resolve a concrete dependency.

## Scope

- Define only M0-required records: scenario dimensions, cells/blocked areas, spawn/target locations, agent seed/count and one service definition with duration/price/stock.
- Use stable definition IDs, version fields and a deterministic content hash. Resolve references once into immutable definitions.
- Add valid single-agent, 50-agent and blocked-passage fixtures; they may load before navigation exists.
- Reject duplicates, missing references, invalid dimensions, nonpositive service durations, negative quantities and unknown schema versions with file/record/field context.
- Put disk I/O in the runner/adapter; pass parsed definitions into the simulation library.

## Acceptance checks

1. Valid fixture loads identically twice with equal content hash.
2. Reordering semantically unordered records does not change the canonical catalogue hash.
3. Each invalid-input category returns an actionable diagnostic without constructing a partial active session.
4. Changing a meaningful tuning value changes the hash.
5. Out-of-bounds and blocked spawn/required target locations are reported.

These are required outcomes, not a prescribed test implementation. Add meaningful automated checks where feasible and report manual observations honestly.

## Exclusions

No complete facility/artist catalogue, unlock tree, mod scripting or data editor.
