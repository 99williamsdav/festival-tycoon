# M0.05 — Versioned save, resume and recovery

Status at authoring: Not started. Milestone: M0 foundation.

## Assignment

A nonempty session saves and resumes identically, while an interrupted or invalid write preserves the previous good save.

Dependencies: M0.04 accepted.

Read [shared execution rules](README.md#shared-execution-rules), then these targeted sections of the repository-root documents: TECHNICAL_SPEC.md §§5, 11, 14; GAME_DESIGN_SPEC.md §18. Read additional sections only when needed to resolve a concrete dependency.

## Scope

- Introduce the persistence adapter and v1 snapshot/header with build/schema/content versions, checksum and complete current authoritative state.
- Include random streams, next IDs, clock, phase, accepted command/transaction identities, wallets, stock and scheduled progress.
- Implement validation before runtime construction, atomic replacement and a prior-good backup.
- Support a named slot in the runner; expose a migration entry point that currently accepts only v1.
- Subsequent briefs must extend snapshots whenever they add authoritative state.

## Acceptance checks

1. Run a fixture, save mid-execution, load and continue; compare final hash and transaction IDs with uninterrupted execution.
2. A paused command followed immediately by save/load remains applied once.
3. Corrupted/truncated saves, unknown schema and incompatible content are rejected with actionable messages.
4. Inject a write failure before replacement; prior-good file remains loadable. Use a controlled temporary test directory.
5. Loading preserves next-ID allocation and random continuation, not just displayed values.
6. Replaying a previously accepted purchase after loading cannot duplicate the sale.

These are required outcomes, not a prescribed test implementation. Add meaningful automated checks where feasible and report manual observations honestly.

## Exclusions

No campaign selection UI, cloud saves, all future schema migrations or live autosave scheduler.

## Demonstration

Runner saves, resumes and compares hashes; demonstrate recovery from a deliberately corrupted copy.

## Handoff and stop condition

Record save format, hash exclusions, file locations and failure handling. Include a checked-in tiny non-personal save fixture.
