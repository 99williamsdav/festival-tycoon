# R0.05ad — changed-state save cadence

Implemented 29 September 2026 under the Producer's explicit relaxed-save direction. Ordinary Build-mode play now saves changed state once per 30 unpaused seconds, plus durable milestones at festival Start, failure/results, Council decision and Return to menu. Routine draft edits, hires, placements, incident actions and live ticks no longer synchronously write to disk. A crash can therefore lose up to 30 seconds of ordinary changes. Existing development capture modes retain their historical save fixtures. No legacy-save migration was added.

The cadence uses a revision marker and one in-flight immutable snapshot writer. Overlapping periods coalesce; a successful write records only the captured revision, so later live changes remain dirty. An IO failure leaves the current session playable and any earlier valid slot intact; an error panel above terminal overlays offers Retry save. A failed Start/Council milestone rolls back its unpublished command. Results/menu stays on the current screen until its milestone succeeds. The atomic rotating-save adapter remains responsible for preserving valid slots.
