# M0.05 result — Versioned save, resume and recovery

Status: Accepted on 8 September 2026. Implemented and self-verified by Codex on Windows x64, then independently reviewed by Astra Low after one repair round.

## Format and mapping contract

`Festival.Persistence` writes UTF-8 JSON through gzip to `.ftsave` files. The v1 envelope is an explicit `SaveHeaderV1` plus `SessionPersistenceSnapshot`; runtime objects are never serialized directly.

The header records:

- format ID `festival-tycoon-save` and schema version 1;
- producing build ID, content hash and ruleset hash;
- campaign ID, UTC ISO-8601 timestamp, session phase and save purpose; and
- lowercase SHA-256 checksum of the canonical authoritative payload JSON.

The payload records every authoritative field currently implemented: campaign identity/seed, PRNG algorithm and every stream state/increment, phase, current tick, pause state, next entity ID, next submission sequence, scheduled fixture progress, sorted completed command IDs, applied command history, wallets, festival cash, owned stock/cost basis, sorted completed transaction IDs, full immutable transaction/ledger records and the simulation authoritative hash.

`GameSession.Restore` validates the DTO before constructing runtime state: enum/algorithm compatibility; nonnegative clock, cash, progress and inventory; exact sorted unique ID collections; contiguous command submission order; entity allocation bounds; owner/target references; complete PRNG streams; transaction-to-command references; exact balanced sale/cost ledger entries; and the reconstructed canonical state hash.

## Canonical checksum and compatibility

The payload checksum serializes the explicit v1 DTO using schema declaration order and its already canonical ID ordering. It excludes header metadata: timestamp, save purpose, build ID, content/ruleset identifiers and presentation state. The simulation's non-authoritative requested display speed is not saved and resumes at its default; it does not affect deterministic simulation hashes.

Load requires schema 1 plus exact content and ruleset hashes. A build-ID mismatch is retained and reported as a warning but loads when schema/content/ruleset remain compatible. `SaveMigrationPipeline.Migrate` is the explicit pre-construction entry point; it currently returns v1 unchanged and rejects every other version with an actionable migration-required message.

## Paths, atomic replacement and recovery

The adapter accepts explicit file paths so tests can use unique temporary directories and a future Godot adapter can supply a per-user data location. `SaveSlot`/`LoadSlot` additionally accept a directory and sanitized slot ID: 1–64 ASCII letters, digits, `_` or `-`, beginning with a letter or digit. The resolved `.ftsave` path is checked to remain directly inside the intended directory.

For a write, the adapter:

1. creates a sibling `.tmp` file with create-new semantics;
2. gzip-serializes, closes the gzip stream and flushes the underlying file to disk;
3. reloads the temporary file, verifies compatibility/checksum and reconstructs the runtime session;
4. invokes the controlled failure-injection point; and
5. validates an existing primary before replacement; if valid, atomically replaces it and rotates that prior-good content into the single `.bak`; if the primary is corrupt, atomically installs the new validated save without overwriting an existing known-good backup; or atomically renames the first save into place.

Any handled write/read/validation failure deletes only the sibling temporary file and returns an actionable result. It does not delete or replace the prior slot. Repeated successful replacements rotate `.bak` to the immediately preceding validated slot. A corrupt current primary is never promoted over a known-good backup.

The reader verifies the gzip header plus the footer CRC32 and uncompressed-size fields itself after decompression. This closes the platform reader's tolerance for missing trailer bytes while keeping gzip framing checks separate from the authoritative payload SHA-256.

## Acceptance mapping

1. `SaveResumeContinuationMatchesUninterruptedHashTransactionsIdsAndRandom` saves after scheduled progress, a purchase and PRNG consumption, then advances both sessions, purchases again and compares final hash, transaction IDs and allocated entity ID.
2. `PausedCommandSavesImmediatelyAndRemainsAppliedOnce` accepts pause, saves without a tick, loads paused, proves ticks do not progress and rejects command replay without hash change.
3. `CorruptionTruncationUnknownSchemaAndContentMismatchAreActionable` covers gzip corruption, truncation, valid-gzip payload checksum mismatch, schema 99, content mismatch and ruleset mismatch.
4. `InjectedFailurePreservesPriorGoodSlotAndSuccessfulReplaceKeepsBackup` injects an `IOException` after temporary validation but before replacement, reloads the byte-preserved prior slot, then verifies two successful replacements rotate a loadable one-generation backup.
5. The continuation test compares the next Weather PRNG output and the next allocated entity ID across uninterrupted/restored sessions, in addition to complete final hashes.
6. `AcceptedPurchaseCannotReplayAfterLoading` rejects both the original accepted command and its transaction ID under a new command, preserving hash, stock, cash and one transaction.

`BuildMismatchIsWarningAndSlotNamesCannotEscapeDirectory` verifies the approved build-compatibility policy and path traversal rejection. `CheckedInNonpersonalV1FixtureLoads` verifies the committed binary fixture, pause state, completed transaction identity and exact authoritative hash.

## Independent review repair round 1

The first independent review found four actionable defects. The repair:

- validates the current primary before deciding whether it may rotate into `.bak`; a corrupt primary is atomically replaced by the new validated temporary file while an existing known-good backup remains untouched;
- validates the gzip footer CRC32 and uncompressed size, rejecting both a missing final byte and a missing full eight-byte footer as corrupted/truncated;
- rejects command ID zero through the normal command path before mutation so restore's identity invariant cannot be violated by a runtime-accepted command; and
- normalizes trailing directory separators before slot containment comparison, accepting valid `\` and `/` forms while retaining traversal rejection.

Regression coverage extends the real file-path tests for corrupt-primary recovery, backup preservation, one-byte/full-footer truncation, zero-ID hash preservation and persistence exclusion, and both trailing-separator forms. Post-repair build and 33 tests pass.

## Independent review

Independent re-review completed on 8 September 2026 using Astra Low. The reviewer confirmed all four first-round findings were closed and all six acceptance criteria passed. Independent verification included a fresh build with 0 warnings and 0 errors, all 33 tests, the M0.05 save/resume demonstration and retained M0.01–M0.04 demonstrations.

Additional probes confirmed first-write and valid backup rotation load correctly; replacing a corrupted primary preserves the prior known-good `.bak` byte-for-byte and loadable; gzip files missing the final one or eight bytes are rejected with actionable footer CRC/size truncation diagnostics; command ID zero rejects atomically without changing the hash and the remaining session still restores; and slot resolution accepts trailing backslash, trailing slash and the `C:\` root while traversal remains rejected. The reviewer also confirmed no temporary file remains after completion, controlled pre-replacement failure preserves the primary, and idempotency, PRNG continuation, next-ID allocation, immediate paused-save behavior, compatibility policy and checked-in fixture all pass.

True crash or power-loss durability was not independently simulated. Evidence is limited to Windows `File.Replace`, `Flush(true)`, gzip/checksum validation and the controlled application failure point immediately before replacement.

## Limitations and stop boundary

- Schema migration implementations beyond the v1 identity path are intentionally absent.
- Campaign year does not yet exist in runtime state; phase is recorded now and future briefs must extend the explicit DTO and hash whenever they add authoritative state.
- Autosave scheduling/three-file rotation, campaign selection UI and cloud saves are excluded. M0.05 implements one prior-good `.bak` for named/manual writes only.
- The adapter accepts explicit paths but does not choose a Godot user-data directory; the future graphical adapter owns that platform decision.
- Crash/power-loss guarantees ultimately depend on Windows/filesystem `Flush(true)` and atomic replace semantics; the controlled failure test covers the application boundary immediately before replacement.
- Manual QA was command-line only because this brief adds no visual behavior.
- M0.06 was not started.
