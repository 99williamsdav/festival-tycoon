# M0.01 result — Reproducible project and Windows build

Status: Accepted on 7 September 2026. Implemented and verified by Codex on Windows x64.

## Build identity and decision

- Build: `0.0.1-m0.01`
- Godot: .NET 4.7.2 stable, Windows x86_64
- Export templates: matching Godot .NET 4.7.2 stable templates
- .NET SDK: 8.0.417 x64, pinned by `global.json`
- Target framework: `net8.0`
- Tests: MSTest.Sdk 4.4.0
- Renderer: Compatibility

Godot 4.7.2 was selected because it was the latest stable maintenance release on the implementation date; 4.8 was development-only. Official Godot documentation requires the .NET editor plus a separate .NET SDK and supports .NET 8 or later. .NET 8 is the conservative supported target shared by Godot and MSTest and was already present in the working environment. The matching editor and templates are downloaded from official versioned URLs, SHA-256 verified, and installed in ignored self-contained mode by `tools/bootstrap-toolchain.ps1`.

## Failures found and resolved

1. MSTest rejected a compile-time-constant assertion (`MSTEST0032`). The smoke result became a callable runtime contract; the meaningful test then passed.
2. The first export attempt found the .NET template directory must be `4.7.2.stable.mono`. Bootstrap was corrected.
3. Godot can exit 0 after a C# export-plugin error. A required game-local solution was added and the export script now rejects logged `ERROR:` entries and missing artifacts.
4. The first clean restore showed Godot export configuration could rewrite lock state with `win-x64` and editor-only packages. Windows RID is now explicit; core projects retain stable locks while the exact-version Godot SDK restore remains configuration-aware and unlocked. A repeated clean cycle passed and left core lock hashes unchanged.
5. PowerShell does not reliably set `$LASTEXITCODE` when directly invoking the GUI-subsystem export. Final launch verification uses `Start-Process -Wait -PassThru` and its process `ExitCode`.
6. Review reproduced that a Release-only build could not instantiate `res://Main.cs` in Godot's development runtime while Godot returned 0. The documented default is now Debug across build, tests, and runner. `run-game.ps1` additionally rejects logged `ERROR:` lines and a missing `FESTIVAL_TYCOON_LAUNCHED` marker. A negative check against the pre-fix Release-only output exited 1 on the logged instantiation error; after a clean Debug build, the same bounded launch exited 0 with the marker.
7. Review found cleanup recursively deleted any directory named `bin` or `obj`. Cleanup now enumerates only exact known generated paths. The unrelated-bin sentinel regression described above passed.
