An independent reviewer repeated the same filtered DLL run: **4 tests, 1 passed, 3 failed** in 188 ms, and confirmed the source causes below. This review did not run the full suite or population diagnostics. The three failures are retained as executable contract expectations rather than marked ignored or weakened:

- `AlreadyReachedWaypointCompletesWithoutMovement`: one person at `(0,0)` with a sole waypoint `(0,0)` stays at route index zero after a tick. The commit branch skips an accepted zero-displacement proposal before consuming its reached waypoint. This is an explicitly feasible completion failure, not evidence of infeasible geometry.
- `BlockedExitPreventsEntryEvenWhenOneStepCrossesWholeCore`: a configured eastbound entrant starts at `(-300,0)`, has a 1,500 mm tick allowance and a first waypoint `(1200,0)`. The core is `[0,1000] × [-100,100]`; another person occupies the east exit berth `(1300,-600)`. The entrant moves across the entire core despite the occupied exit, without becoming an occupant. Endpoint-only core gating misses the swept crossing. Pairwise sweep and speed assertions pass in this reproduction, isolating the admission violation. No maximum speed is imposed by the current kernel API or brief.
- `RestoreRejectsInsidePersonMissingFromRegionOccupants`: advance the existing eastbound fixture three ticks, verify it is Inside, clear the region occupant array in its snapshot, then restore. Restore accepts this inconsistent physical-rights state. Validation checks listed occupants against people but lacks the reverse consistency check.

An initial `dotnet test ... --filter ...` wrapper invocation compiled but did not promptly yield filtered results; it was cancelled. Its results are not claimed. The explicit DLL invocation above is the evidence for the four-test result. No final full suite or solution build was run because the proof did not stabilize. No population diagnostic was intentionally invoked.

## Scope and remaining unknowns

The kernel remains an unintegrated prototype in `Festival.Simulation.TrafficProof`: fixed-point route proposals, pairwise swept rejection, configured east/west regions, simple service state, JSON snapshots and canonical hashes. Existing production navigation, queue ownership, save format, Main, clock and S0.00 fixture are untouched.

Additional inspection concerns are unverified hypotheses, not demonstrated failures: berth availability is checked on admission but is not represented as an exclusive future claim; followers must hit configured entrances exactly to request entry; retarget and service completion transitions need stronger validation. Large-coordinate arithmetic and terrain intersection edge cases also remain unaudited. The tests currently reuse the kernel's pairwise swept predicate, so that predicate needs independent test or oracle coverage before acceptance.

Slow/faster following, continuous bilateral demand, perpendicular/diagonal crossing, stationary terrain, cancellation/retarget, valid save continuation with waiting and inside claimants, service egress, and cycles with/without refuge remain unproved. There is no recovery planner. `EstablishedInfeasible` is defined but not produced; no bounded failure establishes infeasibility. Automatic region extraction and scattered-bay compaction remain outside this proof.

P4 must remain gated on a repaired and independently reviewed P3 contract suite. This checkpoint does not establish general deadlock freedom, supported crowd scale, or production readiness. No commit or push was made.
