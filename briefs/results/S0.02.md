# S0.02 — deterministic contention ownership stop report

Implementation status: **Stopped — negative result; architecture decision needed.** The unchanged baseline trace supported a narrowly scoped ownership experiment, but the initial prototype and its one permitted focused repair both failed bounded completion. All authoritative simulation and test changes were reverted. Only the isolated, non-authoritative runner trace remains. No congested-layout timing, 200-person, snapshot/publication, rendered, R0.01, 500-person or 1,200-person work followed the representative failure.

The retained trace [`baseline-trace-100-representative-20260923.json`](../../reports/evidence/S0.02/baseline-trace-100-representative-20260923.json) observes the unchanged S0.00 decision logic. Its trigger counts stationary ticks while travelling; the selected agent-64 interval is 32 consecutive travelling ticks with no authoritative position change. The generic counter does not reset on non-travelling ticks, so this property should not be inferred for other triggers. The trace also records route index, next waypoint, actual destination, queue lifecycle, reservation, logical order and active service owner.

The earliest valid sustained block was agent 64 at ticks 797–828, fixed at `(6481, 6947)` mm in cell `(140,141)`, intending service approach via next waypoint `(141,141)`. At tick 828, thirteen approaching people were within one metre. None had been admitted to a physical queue slot, none held a reservation and no active service owner existed. Agent 106 also claimed `(141,141)` from roughly 302 mm away, while other nearby people claimed adjacent or opposing cells. This is evidence of pre-admission local corridor contention, not service delay. An earlier Euclidean-distance trigger was discarded because it classified a legitimate obstacle detour as non-progress.

The same unchanged run completed **100/100 purchases at tick 22,314**, with no final backlog or reservations and authoritative hash `e687cfc3de84dbed846edd4c6eddec47de0093758d88839a0cb7a7274203bc0b`.

## Rejected prototypes

The first prototype assigned each next-waypoint cell to the claimant with greatest persisted yield age, then stable ID. It incorrectly grouped distant agents that happened to share a later waypoint. The focused repair limited ownership to claimants sharing the same next waypoint within 600 mm; this bound covered the observed 302 mm conflict. Both versions persisted, validated and canonically hashed fairness age. The diagnostic established boundary restore/hash equality; it did not independently establish post-restore continuation for every counter state.

The initial prototype reached tick 25,000 with **36/100 purchases**; the focused local repair reached tick 25,000 with **42/100**. Both reported zero route failures, exact boundary save/restore hashes, no final logical queue backlog and released slot/exit reservations, but neither completed every person or met the full-population wallet and sales totals. Those failed totals reflect incomplete purchases, not independent evidence of financial corruption. The local repair also failed the arrival timing targets. These facts establish a bounded-completion regression; they do not establish why unresolved approaching people failed to complete or prove a permanent deadlock.

## Verification and stop decision

- Base revision: `90042c0` (the committed S0.01 report); the authoritative runtime code remained the accepted S0.00 implementation. Both rejected prototype JSONs identify this base revision. The baseline trace JSON predates the source-labelled diagnostic schema and omits a revision/fingerprint field; its provenance is this report's command/context and the unchanged baseline final tick/hash, not a self-contained source label.
- Release runner builds completed with 0 warnings and 0 errors.
- Existing focused navigation/queue/save/scale tests passed **43/43** for the initial prototype.
- The repaired focused suite, including narrow-gate yielding, variable walking speeds, later physical progress, swept walkability and exact save continuation during contention, passed **44/44** in 1m 12s.
- Initial/repaired source fingerprints: `55f5b293126ba460d10f049386933e46a48321c8` and `f4ea664a4522f4a7e34f5184d1d3b75b3a110a89`.
- Rejected reports are retained as [`prototype-100-representative-20260923.json`](../../reports/evidence/S0.02/prototype-100-representative-20260923.json) and [`repaired-100-representative-20260923.json`](../../reports/evidence/S0.02/repaired-100-representative-20260923.json).

The focused test success did not override the unchanged scale fixture’s completion failure. Per the brief, the implementation was reverted after the single repair and no congested-layout or larger-population run was made. A broader reservation/traffic system, different local-progress model, or product-level capacity decision now requires separate approval; this spike selects none of them.
