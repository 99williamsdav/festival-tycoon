# S0.05 — authoritative stepping and observation publication (P2)

Implementation status: **Accepted after independent re-review.** The foundation production presenter and the unchanged scale diagnostic now advance authoritative ticks without automatically constructing and hashing a full `SessionSnapshot`. P1 navigation is unchanged. P3 traffic work and R0.01 gameplay were not started.

## Architecture and compatibility

`GameSession.AdvanceWithoutSnapshot(count)` and legacy `AdvanceTicks(count)` share one private authoritative stepping implementation. The legacy method still returns a complete canonical snapshot and events on every call, including paused/zero/frozen calls; `CaptureSnapshot()` remains explicit, stable and hash-bearing. The new method returns the same ordered events but performs no implicit snapshot or SHA-256 work.

`CaptureObservation()` is a detached, bounded read model containing every navigation identity, integer position, action and intent plus every queue identity, ordered membership, active owner, service countdown, agent action, slot/exit assignment and ownership, physical-at-slot state, wallet count and transaction count. It contains no route, ledger or canonical hash. Observation requests do not mutate authoritative state.

The actual foundation loop in `game/Main.cs` uses one snapshot-free step and one compact observation per scheduled tick. Presentation interpolation and attendee inspection consume that observation. A complete snapshot/hash is still published every 80 authoritative ticks, on capture automation, on save/load verification and at other explicit verification boundaries. The HUD labels the cached value `HASH@<tick>`, so an older published hash is not represented as the current tick's hash. Capture automation continues to receive a complete snapshot each captured frame. This migration is deliberately scoped to the foundation production loop; unrelated shared-world capture automation still uses its existing legacy path.

The scale runner uses the same snapshot-free step and compact observation. Timed samples contain authoritative advance plus observation construction. The every-person invariant predicate runs immediately after the timer, as it did for the old snapshot predicate; current-thread allocation includes both observation construction and predicate evaluation. The predicate checks navigation/queue identity-set equality, unique queue/exit reservations, ordered-member membership in the global agent set, active-owner/action consistency and failed/completed status. It does not independently prove same-queue membership for every ordered member. Therefore the measured improvement is the end-to-end publication-path change (full snapshot/hash replaced by compact observation), not a claim that navigation itself became faster.

## Differential proof

Four focused publication tests cover:

- legacy one-tick publication versus snapshot-free stepping with identical event payload/order, intermittent observations and hashes, pause/resume, queue cancellation, purchases, and final canonical state;
- a snapshot-free purchase interval followed by persistence restore and 173 snapshot-free continuation ticks with exact events, observations and final hash;
- mixed multi-tick batches over the 50-person variable-walking-speed fixture whose initialization includes deterministic queue retargets;
- detached observation arrays, stable repeated explicit snapshots, every-person queue ownership, and legacy snapshot-presenter versus compact production-presenter samples at two interpolation fractions.

The initial focused batch passed 111/112; its only failure was a new test assumption that every retargeted fixture agent must always hold a queue slot. The production result was not divergent. The assertion was corrected to check actual reservation uniqueness, membership and ownership. The enhanced final focused publication set passed **4/4** in 2.629s. The broader current-source suite later passed **114/114**.
