The remaining measured failure is frame pacing: median and tail callbacks exceed the 16.667 ms budget, so the run is not stable 60 FPS. The 4× window attained 3.953× without skipped authoritative ticks. Save/load durations pass their numeric targets, while actual input responsiveness during those synchronous operations remains unmeasured.

3. Reduce M1's playable crowd below 50 and define a new measured gate. This is a product-scope change and does not repair the future 50/1,200 targets.

## Focused review repair

A single post-implementation repair confirmed and fixed two validation defects without changing the fixture, rendered evidence or failed performance gate:

- Persistence now rejects null queue collections before cross-queue uniqueness scans, so malformed multi-queue snapshots return structured failures instead of dereferencing null. Focused cases cover null members/agents/slots/exits and cross-queue duplicate attendee, slot and exit ownership.
- Initialization and restore require enough queue slots for every deterministic exit index. Fixture retargeting additionally derives both admission and allocation from the paired `min(slots, exits)` capacity. A `slots=1, exits=2` destination is rejected without mutation; a safe unequal `slots=3, exits=2` destination retargets and round-trips exactly.

Post-repair solution build passed with 0 warnings/errors. The test runner ignored the requested class filter and ran the complete suite: **89/89 passed**, 0 failed, 6m 06.4s. Expensive rendered measurements were not rerun because authoritative fixture and presentation behavior did not change.

## Monotonic measurement repair

A targeted evidence review found that the earlier rendered report used Godot `_Process(delta)` both as frame duration and in the attained-speed denominator. That engine value is scheduling input, not an independent wall clock, so the superseded rendered numbers could not support the gate.

Instrumentation now records monotonic `Stopwatch` intervals between completed presented callbacks and computes attained speed from exact authoritative tick difference divided by `80 × independent wall elapsed seconds`. Each 1×/4× window starts on a subsequent clean frame after restore and reports exact boundary ticks, sample frames/ticks, wall elapsed, wall percentiles, engine-delta telemetry and simulation-work stopwatch percentiles separately.

The measurement-only change built with 0 warnings/errors. One visible exact-child Windows export rerun completed inside the 120-second bound with all 50 active/interacting throughout. No headless or full-suite rerun was warranted because production scheduling, simulation and fixture behavior did not change. The new monotonic results above supersede all earlier rendered timing claims; the gate remains failed because stable 60 FPS is not met and input latency is Unverified.
