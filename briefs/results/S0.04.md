# S0.04 — exact-result pathfinder optimization (P1)

Implementation status: **Accepted after independent review and one focused repair.** P1 replaces the linear open-list scan and hash-based per-search state with an indexed binary heap plus per-call pooled arrays. It preserves the frozen algorithm’s results in the differential suite and unchanged scale fixtures. P2 snapshot/publication and P3 traffic-kernel work were not started; R0.01 remains paused.

## Implementation and exactness

`DeterministicPathfinder.FindPath` still uses the same neighbour order, integer edge costs and heuristic, diagonal corner rule, relaxation/reopen behavior, maximum expansion bound and total tie order `(f, h, Z, X)`. Grid cells are represented by their stable `Z * 256 + X` index. The heap supports exact decrease-key behavior, while score, predecessor, state, heap and heap-index arrays are rented for each call and returned in `finally`.

The independent review identified two reachable extreme-cost equivalence gaps. An undiscovered node now uses its separate state byte rather than `int.MaxValue` as the discovery sentinel, so a first valid tentative score of exactly `int.MaxValue` is accepted like the reference dictionary. An updated open node is reheapified upward and then downward: decreasing `g` is not necessarily a monotone priority improvement because the frozen reference intentionally compares unchecked signed `g + h`, which can wrap. These repairs do not change ordinary fixture decisions.

There is no mutable planner instance or shared authoritative cache. Concurrent or interleaved calls rent independent working arrays; `ArrayPool<T>.Shared` supplies storage but no rented contents influence results because every decision-bearing range is initialized before use. The returned route is an independent list. This makes the pathfinder re-entrant under the existing read-only-grid assumption.

The test-only frozen implementation is the pre-P1 algorithm copied without optimization. Differential tests cover open and same-cell routes, blocked endpoints, diagonal/corner constraints, weighted-cost detours, a genuinely enclosed unreachable target, an orthogonal labyrinth whose reference route score is exactly `int.MaxValue`, forty seeded random obstacle/cost grids, reversed repetition and interleaved calls. Every case matched found status, full ordered route and `ExpandedNodes`.

The independent re-review found the reported exactness gaps resolved. The exact-maximum fixture exercises the discovery sentinel repair; the signed-overflow decrease-key fix is supported by code inspection but does not yet have a dedicated reproducing test. This is a confidence limit, not evidence of a current mismatch.

## Evidence and limitations

JSON is retained under [`reports/evidence/S0.04`](../../reports/evidence/S0.04/). The runner wrapper enforces a 120-second child bound but does not serialize exact end-to-end wall duration, so completed runs are reported only as completing within that bound; the congested 200 child was stopped at the configured 120-second timeout. GC counts and allocation remain process/current-thread counters rather than allocation call-stack attribution. Timing comparisons are separate processes on one machine and naturally noisy. No rendered, input-latency, P2, P3, R0.01, 500-person or 1,200-person work was performed.
