# R0.05u save-boundary movement follow-up

28 September 2026. The user's more precise reproduction was that people stop walking when a save occurs, even while the camera remains responsive. This is distinct from frame-rate stutter. The previous worker-backed boundary save intentionally scheduled zero authoritative ticks until persistence completed; the awake R0.05r live trace had eight save windows with no tick progress, including a 965 ms window. The later R0.05s trace included an anomalous 1,593 ms pending window (the machine was in Modern Standby), so the awake R0.05r trace is the cleaner comparator.

The normal game now advances a boundary tick immediately, captures its immutable post-boundary checkpoint, and continues ordinary authoritative ticks while a worker restores/validates/writes that checkpoint. A failed write restores the pre-boundary snapshot, resets clock debt and presentation interpolation, and restores attendee visibility/picking before blocking for retry. User actions remain blocked while an in-flight save owns its checkpoint. Periodic autosaves now capture on the presentation thread and write on a worker; if one overlaps a boundary, the boundary write is sequenced after it and assigned the next save generation. A further boundary encountered while a boundary write is pending is held until that write finishes, preserving save order and failure rollback rather than allowing unbounded speculative transactions.
