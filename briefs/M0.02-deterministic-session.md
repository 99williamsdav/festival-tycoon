# M0.02 — Deterministic clock, IDs and commands

Status at authoring: Not started. Milestone: M0 foundation.

## Assignment

A headless session produces the same authoritative state for the same seed and commands regardless of how ticks are batched.

Dependencies: M0.01 accepted.

Read [shared execution rules](README.md#shared-execution-rules), then these targeted sections of the repository-root documents: TECHNICAL_SPEC.md §§3–4, 14; GAME_DESIGN_SPEC.md §3. Read additional sections only when needed to resolve a concrete dependency.

## Scope

- Implement stable entity IDs, fixed festival ticks, a minimal session phase, ordered command envelopes/results and versioned independently owned random streams.
- Implement only fixture commands needed to create a small state record, change its value and pause/resume. Clearly mark fixture commands as test/runner support.
- Provide canonical state hashing that excludes wall-clock metadata and presentation state but includes simulation state, ID allocation and random-stream state.
- Provide pause and requested speed state. The runner advances explicit ticks; real-time scheduling belongs to M0.09.
- Include the smallest scheduled counter/expiry to prove time actually advances rather than hashing an empty world.

## Acceptance checks

1. Same seed and commands run twice produce identical intermediate and final hashes.
2. Advancing 400 ticks in one batch versus batches of 1/7/32 yields the same state.
3. Paused advance requests leave scheduled state and time unchanged; a valid paused command changes its target without advancing time.
4. Wrong-phase/unknown-target commands are rejected with stable reason codes and no partial mutation.
5. Equal-tick commands follow submission order; duplicate submission of a previously accepted command ID does not apply twice.
6. Consuming a cosmetic or unrelated random stream does not change the tested gameplay stream.

These are required outcomes, not a prescribed test implementation. Add meaningful automated checks where feasible and report manual observations honestly.

## Exclusions

No world scene, gameplay need system, money, disk saves or full future campaign state machine.

## Demonstration

Run the deterministic fixture and compare hashes for different tick batch sizes.
