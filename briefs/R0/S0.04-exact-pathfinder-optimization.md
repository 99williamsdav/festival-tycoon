# S0.04 — exact-result pathfinder optimization (P1)

Status: **Accepted after independent review.** Exact 100-person completion/tick/hash identity and material route-search improvement are recorded in the [S0.04 result](../results/S0.04.md). First stage of the approved [S0.03 architecture sequence](S0.03-movement-architecture-review.md). R0.01 remains paused. Snapshot/publication and traffic-kernel work are separate later stages.

## Outcome

Reduce route-search time and allocation without changing any authoritative decision. The existing `DeterministicPathfinder.FindPath` is the reference: same found/not-found, full ordered path, `ExpandedNodes`, neighbour order, integer cost/heuristic, tie order `(f,h,Z,X)`, relaxation/reopen semantics and route-search timing boundary. `LastSearchExpandedNodes` is saved and hashed; an apparently equivalent path with a different expansion count is a regression.

Use an indexed priority queue and/or reusable arrays/generation stamps if they meet that exact contract. Do not alter occupancy, collision, sidesteps, queues, tick rate, identities, wallets, saves or terrain semantics. Avoid mutable shared planner state that could make calls order-dependent or non-reentrant; document any thread-safety assumption.

## Proof and measurement

1. Keep a test-only frozen reference implementation of the old algorithm. Differentially compare path and expansion count across representative open, obstacle, diagonal/corner, weighted-cost, unreachable and seeded random grid/start/target cases, including repeated and interleaved calls. Verify public no-route and same-cell behaviour. Existing navigation/queue/save tests must pass.
2. Run unchanged 100-person representative and congested scale fixtures for seed `20260923`, plus representative seed `20260924`. Assert full completion/reconciliation, original completion tick and final authoritative hash for matching seed/layout, not only timed-window speed. If hashes change, stop and investigate before treating the optimization as successful. Preserve old JSON as reference evidence.
3. Report same diagnostic windows, route searches/nodes, route time, tick mean/p95/p99, allocation/GC and wall time. A material speedup is desirable but not sufficient without exactness. If no useful speedup or allocation gain is measured, report that honestly and consider reverting complexity.
4. If 100-person correctness and performance justify it, run one bounded 200-person representative and congested headless probe. Partial congested completion is still partial. No rendered claim or 500/1,200 run follows automatically.

## Stop and review

One focused repair pass is permitted after a failed differential or completion check. If still failing, revert the experimental pathfinder and document a negative result. One fresh independent reviewer checks algorithm equivalence, tests, evidence and source scope; re-review only actual repairs. Run one final full suite only if targeted checks stabilize. No push or R0.01 work. Do not fold P2 or P3 into this change.
