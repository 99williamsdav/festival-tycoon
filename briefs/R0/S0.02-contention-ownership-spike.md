# S0.02 — deterministic contention ownership spike

Status: **Stopped — negative result; decision needed.** The initial ownership prototype and one focused repair both failed bounded representative completion and were reverted; see the [S0.02 stop report](../results/S0.02.md). Follows the stopped [S0.01](../results/S0.01.md). R0.01 gameplay remains paused. No population, tick-rate, per-person identity, wallet, physical access or off-camera-causality concession is authorized.

## Question

Can explicit, deterministic yielding/ownership at contested corridors and service queue slots preserve completion while reducing avoidance-owned global route searches? Do not assume that the S0.01 regression was a permanent deadlock or that reservations are already proven superior.

## Investigation order

1. On the unchanged S0.00 baseline, capture a bounded, source-labelled trace around the earliest sustained non-progress or contention in the 100-person representative fixture. Distinguish blocked ticks from useful progress toward the actual destination, queue admission, slot compaction, service and exit. Identify the involved people, cells, routes and ownership transitions without changing authoritative decisions. Preserve a baseline completion check.
2. Specify a small, deterministic right-of-way rule for that observed conflict. Prefer stable ownership/yielding around one narrow path or queue-slot transition over an unbounded full-world traffic system. No teleport, overlap, fence crossing, queue bypass, arbitrary freezing or early service. Any state affecting decisions must be canonical, persisted and validated; old saves must remain loadable or an explicit compatibility decision must be raised before proceeding.
3. Implement the smallest testable prototype. Add focused adversarial tests for two-way contention, variable speeds, fairness/release/cancellation, queue service and exit, deterministic continuation from a save taken during contention, and obstacle sweeps. Show useful destination-progress and eventual completion, not only lower blocked age or fewer A* calls.
4. Run the focused suite and the unchanged 100-person representative and congested diagnostics, with the same tick bounds and windows. Compare completions, purchases, backlog, reservations, route failures, avoidance searches, timing and allocations to S0.00. Only if both are correct should 200-person headless probes be considered. Snapshot/publication optimization and rendered claims remain out of scope.

## Stop and review

If the trace does not support an ownership rule, stop with evidence before implementing. If a prototype fails bounded completion or another invariant, allow one focused repair pass, then revert and escalate if still failing. Do not repeatedly tweak heuristics to chase a timing number. A fresh independent reviewer checks the evidence and implementation; re-review only repaired findings. No push, R0.01 work, 500/1,200-person runs or population/clock/fidelity change. A negative result is a valid spike result.
